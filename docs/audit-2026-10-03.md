## 2. Do the functions do what they're for?

TL;DR items 1–10 are the most serious. Below are the rest, plus details.

### Streaming / engines
- 📖→✅ **qBittorrent has no `piecePrio` endpoint** (checked against qBittorrent's `torrentscontroller.h`). All piece-priority code is therefore dead on the only engine that claims to support it. Worse: after a seek past the download edge, the recovery **turns sequential download off** and then cannot prioritise the playhead, so the stream keeps stalling (`playback_health_monitor.dart:867-909`, `qbittorrent_api_service.dart:905`). ✅
- 📖 **Season-pack piece maths assumes each file starts at a piece boundary.** For later files in a pack, the proxy reports bytes as ready when they aren't and serves zeros, which is the corruption the proxy exists to prevent (`local_streaming_server.dart:503-528, 856-880`). The tests only cover piece-aligned files.
- 📖 Login fails against qBittorrent 5.2 (cookie `QBT_SID_<port>`, empty success body) (`qbittorrent_api_service.dart:192-212`). There is also no re-login on 403 after a qBittorrent restart.
- 📖 Next-episode prefetch from the same season pack sets the **currently playing episode's** files to priority 0 (`streaming_service.dart:569-584`).
- 📖 The metadata timeout is applied to the wrong condition: a dead magnet spins forever, while a healthy session over 2 minutes old fails on one transient error (`streaming_service.dart:385-449`).
- 📖 `assessBuffering` reports "ready" at 8 MB of scattered data, so stalls are never detected and polling runs forever (`streaming_service.dart:139, 832`).
- 📖 Valid file headers are rejected (MPEG-PS, M2TS, WMV, FLV, QuickTime starting with `wide`) (`local_streaming_server.dart:369-387`).
- 🧪 The seek bar's buffered-range painter spans the full width, but the slider is inset 12 px. Clicking the visible buffered edge seeks into undownloaded data (`seek_bar.dart:135-175`).
- 📖 Every settings change rebuilds the engine, because the providers watch the *whole* settings object (`connection_provider.dart:78, 110`). Each rebuild kills the crash-restart health loop and tears down streams that are still buffering. Settings fields save on every keystroke, so typing port `7000` points the engine at 7, 70, 700 in turn.

### Library, watched state, TMDB sync
- 🧪 The movie is resolved as the first TMDB search hit with the year stripped. Finishing "Dune.1984…" **rates the wrong Dune** on the user's TMDB account (`watch_progress_provider.dart:337`, `library_actions.dart:39-60`).
- 📖 One unreadable entry wipes the **whole watch history** on the next save (`watch_progress_provider.dart:273`). Auto-download state has the same problem with unchecked enum indexes.
- 📖 Plaintext credentials kept as a Keychain fallback are lost on the next settings save (`secret_store.dart:351-407`, `settings.dart:154`).
- ✅ Show details: failures print a raw `Error: $error` with no retry and no back button (`show_details_screen.dart:411`).
- ✅🧪 The Home "Because you liked" row crashes on shows with no year or poster (`show?.year ?? movie!.year`, `home_recommendations_provider.dart:24-25`).
- ✅ **Movies/Shows:** switching filter while a page is loading mixes the old filter's results into the new list and skips a page. Errors on page 2 and later are silent (`movies_screen.dart:109-141`, `shows_screen.dart:107-141`).
- ✅ **Settings → Reset** switches built-in users to qBittorrent (`AppSettings()` instead of `freshInstallDefaults()`) and doesn't clear Keychain secrets (`settings_provider.dart:308`).

### Calendar / favourites (seen in the running app)
- ✅ Calendar says **"Add shows to your favorites"** to a user who has 4 favourites. It fetches −7…+30 days, and the empty state never considers "has favourites, nothing airing" (`calendar_screen.dart:233-239`).
- ✅ Favourites shows "In 277 days" for an episode 278 calendar days away, and "Today" for tomorrow in the evening.
- 📖 Every calendar row shows "12:00 AM" (TMDB dates have no time), and yesterday's episodes say "SCHEDULED".
- ✅ AUTO-GRAB always fails, because `/tv/{id}` has no `imdb_id` (`calendar_screen.dart:340`, `show.dart:136`).

### Player & UI logic
- ✅ Player errors are only logged (`player_provider.dart:52`). A bad or zero-filled file shows a black screen with no message, and four play paths skip `isFileCompleteOnDisk`.
- 📖 Mute toggles volume between 0 and 100, so volume 30 → M → M gives 100 (`volume_control.dart:47`, `player_provider.dart:464`).
- 📖 Next-episode overlay: if the countdown arrives after it is already showing, it freezes at "0s" (`next_episode_overlay.dart:76`).
- 📖 Add-torrent dialog:
  - no magnet/URL check;
  - after picking a .torrent file you can't go back to a magnet;
  - closing it during "Adding…" calls setState after dispose.
- 📖 Episodes drawer:
  - quick-jump does nothing for rows not yet built;
  - a paused torrent at 10% shows as DOWNLOADED;
  - shows are matched on the first word of the title ("The…").
- 📖 Source picker: ★BEST marks the first 2160p row (possibly 3 seeders), not the best source (`mediahub_torrent_drawer.dart:217`).
- 📖 Peer country flags render wrong because qBittorrent sends lower-case codes (`torrent_peers_tab.dart:181`).
- 📖 On rqbit, the Info and Peers tabs show placeholder values the engine doesn't provide ("Added: Unknown", "Pieces Have 0" at 100%).
- 📖 Turning binge watching off also disables the Continue Watching pill, the OpenSubtitles lookup for Library files, and linking progress to the show.
- ✅ The Home "Airing tonight" panel is hard-coded to `count: 0` (`mediahub_home_screen.dart:346`).

## 3. Code quality

**Strengths:**
- The lint set is strict and enforced in CI, and the analyzer is clean.
- Comments explain the reasons behind decisions.
- Shutdown and secret storage are written defensively.
- Spacing and radius tokens are used consistently.
- 737 tests.

**Three root causes behind many of the bugs:**
1. **Watching the whole `settingsProvider`** (engine, process, the Transfers filter and sort). Any setting change resets unrelated state. → use `select` on the fields actually needed.
2. **Models whose `==` compares only the id** (`Torrent`, others). Providers silently stop notifying. → use value equality, or select specific fields.
3. **Seven hand-written prefs stores**, each handling corrupt data differently (quarantine, wipe, reset, or ignore). → one JSON store with quarantine and a version number.

**Other issues:**
- **Async lifecycle:**
  - `void … async` functions and Futures dropped from `initState` are invisible to `unawaited_futures`. → enable `discarded_futures` and `avoid_void_async`.
  - `library_actions.dart` takes a `WidgetRef` for long network work, which throws once the widget unmounts.
- **God files and functions:**

  | File / function | Lines |
  |---|---|
  | `streaming_service.dart` | 1,222 (`_handleFileSelection` 214) |
  | `local_streaming_server.dart` | 1,007 |
  | `playback_health_monitor.dart` | 977 |
  | `qbittorrent_api_service.dart` | 974 (the same auth boilerplate 26 times) |
  | `connection_tab` `build` | 489 |
  | `reconcileWatchedWithTmdb` | 223 |
  | `findTorrentForEpisode` | 214 |

- **Business logic inside screen files:**
  - the calendar data model, its 4 providers and the TMDB fetch loop are in `calendar_screen.dart`;
  - the TMDB lookup chain is in `home_hero_data.dart`;
  - the torrent file priorities are in `show_details_screen`.
- **qBittorrent assumptions in engine-neutral code:**
  - the default engine's users see "qBittorrent" error text;
  - both engines return `[]`/`false` on errors, so callers can't tell "empty" from "engine down".
- **Missing tests where the bugs are:**
  - all of `lib/screens`;
  - the player widgets;
  - `ConnectionNotifier`;
  - torrent-list delta merging;
  - auto-download orchestration;
  - the proxy's HTTP path;
  - qBittorrent's HTTP behaviour;
  - the local-file matchers.

  Some existing tests miss real bugs:
  - the UiScale tests never check the child's constraints;
  - the buffering tests use an 80 MB threshold where production uses 8 MB.
- **Performance:**
  - Torrent rows animate forever, so the app never goes idle on Transfers. This undoes `7692418`.
  - The library grid is shrink-wrapped, so it builds every card at once: up to 500 TMDB searches.
  - Backdrops load TMDB `/original` images with no disk cache.
  - Video controls rebuild every frame.
  - Home rebuilds on every 2 s poll.
  - The calendar makes N×3 sequential TMDB calls and refetches them on *any* favourites change, including movie favourites.
- **Release logging** writes every DEBUG line to disk, which rotates away the startup and error lines.
- **Magic numbers:** completion thresholds 0.999 / 0.995 / 0.99 / 0.95; connection checks of 30 s vs 5 s; raw file priorities 0 / 7.
